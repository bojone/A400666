## 1. 分解与模 9 必要条件

$$c(17)=1234567891011121314151617=9\cdot47\cdot4993\cdot P,$$

其中

$$P=584538396786764503,\qquad R=97423066131127417,\qquad P-1=6R.$$

拼接数的十进制 digit sum 给出

$$c(k)\equiv\frac{k(k+1)}2\pmod 9.$$

因此只需考虑 $k\bmod9\in\{0,8\}$，写成

$$k=a+9j,\qquad a\in\{0,8\}.$$

两个剩余类分别搜索，每类再分为四个分片，正好使用八张 GPU。

## 2. 2–20 位：小因子剩余类与 CPU 过滤

对固定位数 $d$ 和模数 $m$，令 $q=10^d\bmod m$。在 $q\ne1$ 时，闭式为

$$c(k)\equiv Uq^k+Ak+B\pmod m,$$

$$A=(1-q)^{-1},\qquad B=-q(1-q)^{-2}\pmod m.$$

对 $m=47$ 和 $m=4993$ 分别求出一个完整周期内的零剩余类，再用中国剩余定理合并，并加入上面的模 9 条件。$q=1$ 的退化情形由生成器单独处理，不在此套用逆元公式。

- 2–6 位直接穷举。
- 7–20 位只扫描合并后的剩余类，而不是该位数的全部整数。
- 过滤器用 AVX-512 的八个 64 位 lane 并行递推大素因子余数，以 272 个 OpenMP 工作线程处理独立组。
- 每组完成后记录位图、已扫描点数和完整候选数。重启时检查位图与点数一致，已完成组不会重算。

20 位共检查 **85,225,698,957,274** 个过滤后候选点，完整解为 0；2–19 位也全部为 0。过滤器剩余类及生成审计见 [filters/](filters/)，逐位覆盖证据见 [results/filter_d*.audit.txt](results/)。

## 3. 21–24 位：把大素因子条件化为一次同余

GPU 主搜索先处理 $P$，完整候选再复核 47 和 4993。对固定的 $d$，仍令 $q=10^d\bmod P$，并定义

$$g=q^9,\qquad L=\mathrm{ord}_P(g),\qquad D=9AL.$$

实际使用的 21–24 位均满足

$$L=\begin{cases}R,&d\text{ 为偶数},\\ 2R,&d\text{ 为奇数}.\end{cases}$$

这些阶由 [orders17.audit.txt](results/orders17.audit.txt) 独立记录。令

$$j=x+Lt,\qquad 0\le x < L.$$

由于 $g^L=1$，项 $g^j$ 不再依赖 $t$。零剩余条件变为

$$t_*=\alpha g^x+\beta x+\gamma\pmod P,$$

$$\alpha=-Uq^aD^{-1},\qquad \beta=-L^{-1},\qquad \gamma=-(Aa+B)D^{-1}\pmod P.$$

所有解都必须满足 $t=t_*+mP$，其中 $m\ge0$ 为整数。每个轨道点因此主要是一次线性同余求值，而不是对一个巨大拼接数做除法。

实际边界为

$$j_{\min}=\left\lceil\frac{10^{d-1}-a}{9}\right\rceil,\qquad j_{\max}=\left\lfloor\frac{10^d-1-a}{9}\right\rfloor.$$

21–24 位的 $\lfloor j_{\max}/L\rfloor$ 都小于 $P$，所以 $t_*+P$ 必然越界，只需检查 $t_*$ 本身。这是专用 `SINGLE_T` 分支的数学依据，并未省略合法的第二个边界点。

各数位的总轨道点数和审计结果为：

| 数位 | 每个 $a$ 类的轨道长度 | 两类总点数 | 预命中 | 完整解 |
|---|---:|---:|---:|---:|
| 21 | $2R$ | $4R$ | 346 | 0 |
| 22 | $R$ | $2R$ | 3,446 | 0 |
| 23 | $2R$ | $4R$ | 34,413 | 0 |
| 24 | $R$ | $2R$ | 343,046 | 1 |

这里 $R=97423066131127417$。预命中只表示通过 $P$ 的初筛，不等于完整解。

## 4. CUDA 内层循环

kernel 维护

$$z_x=\alpha g^x,\qquad w_x=\beta x+\gamma\pmod P.$$

每个轨道点执行：

1. 用 Montgomery 乘法更新 $z_{x+1}=z_xg$；
2. 用负步长模加更新 $w_{x+1}$；
3. 计算 $t_*=z_x+w_x\bmod P$；
4. 若 $t_*$ 超出上界，立即进入下一点，避免 128 位坐标重建；
5. 对极少数界内点恢复 $j$ 和 $k$，由宿主端复核 47、4993 及模 9 条件，再由 Python 独立验证完整复合模数。

固定 Montgomery 乘数选为奇数。非零轨道值乘奇数后低位乘积非零，因此 Montgomery 约减中的进位恒为 1，可省掉一次条件判断。内层循环计数器使用 32 位，但命中坐标始终保留 64 位。

最终生产参数为：展开 16 次、每个 block 128 线程、每线程连续处理 262,144 点、每次启动 32,768 个 block。每个分片以原子替换写入 `.state`，记录精确配置、终点、预命中数和完整候选数。

## 5. 实测优化过程

设备为 **8 张 NVIDIA GPU**，CUDA 12.9；CPU 过滤器使用 AVX-512。生产二进制 SHA-256 为

```text
e8b5545c5dc0d409fb4c9e01334a6f0e0dd1ebbd81af691b28925090e15a8f8c
```

主要实测阶段如下，速率均为每 GPU 每秒轨道点数：

| 改动 | 速率 | 处理 |
|---|---:|---|
| 初期周期 kernel | $3.390\times10^{11}$ | 基线 |
| 提前跳过越界 $t$ | $4.278\times10^{11}$ | 采用 |
| 单一边界点、奇乘数和负步长 | $4.722\times10^{11}$ | 采用 |
| 展开与 block 参数调整 | $5.215\times10^{11}$ | 采用 |
| 128 线程、chunk=262144 | $5.23675\times10^{11}$ | 采用 |
| 32 位内层计数器 | 约 $5.3388\times10^{11}$ | 采用 |

最后一次 32 位计数器实验在交替真实负载中提速 **1.966867%**，生产环境观测约 **1.9437%**。部署前通过了自检、22 位含预命中区间和 24 位非整段尾部的等价对照，再从合法断点恢复。详见 [优化审计](results/counter32_optimization.audit.txt) 和 [speed_history.log](results/speed_history.log)。

最终每卡约 $5.3388\times10^{11}$ 点/秒，是初期单卡速率的约 1.57 倍；八卡合计约 $4.2711\times10^{12}$ 点/秒。展开 32 次、32 位 Montgomery 拆分、其他模加写法及降低 warp 占用率的实验均更慢，没有部署。相关源码放在 [experiments/](experiments/)，生产版本在 [src/search17.cu](src/search17.cu)。

## 7. 独立验证与审计范围

[src/verify17.py](src/verify17.py) 使用二进制块和递推，[src/verify17_matrix.py](src/verify17_matrix.py) 则独立使用 $3\times3$ 矩阵快速幂。追加一个 $i$ 时，对状态 $(r,i,1)^T$ 的变换为

$$T=\begin{pmatrix}q&1&0\\ 0&1&1\\ 0&0&1\end{pmatrix},\qquad q=10^d.$$

矩阵法与 200 个直接拼接的小例子及另外 103 个块和法结果交叉核对。两种方法都在完整的 $c(17)$ 下得到余数 0，而不是只验证 $P$。

直接构造本答案的 $c(k)$ 需要约 $1.31835\times10^{25}$ 个十进制位，因此验证器使用等价的模运算，不生成这个无法存放的十进制字符串。

`make audit` 会检查所有分片配置、精确终点、完成日志、CPU 位图、理论覆盖点数、候选坐标和完整模数余数，并确认更低位没有解。它不是在几秒钟内重新穷举全部空间；最小性依赖随附的完整搜索证据、算法覆盖证明和独立候选验证。

## 8. 构建、审计与重跑

从项目根目录执行：

```bash
# 不需要 GPU，也不需要 SymPy：覆盖审计及两种独立余数验证
make -C a17 audit

# 数值自检与矩阵验证
make -C a17 validate

# 编译 CUDA 和 CPU 过滤器，不启动搜索
make -C a17 NVCC=/usr/local/cuda-12.9/bin/nvcc GPU_ARCH=native

# GPU 数值自检和 AVX-512 自检
make -C a17 selftest GPU_ID=0

# 查看保存的断点
make -C a17 status
```

审计和验证只使用 Python 标准库。只有重新生成小因子剩余类时，`residues17.py` 才需要 SymPy；本环境版本为 1.14.0，可执行 `python3 -m pip install -r a17/requirements.txt`。

完整复现入口为：

```bash
make -C a17 run
```

它依次运行 2–20 位 CPU 过滤、21–24 位 GPU 搜索和最终审计。随附结果已经完成，所以该命令会复核或跳过已完成分片，而不是从头重扫。若要独立重跑，请复制 `src/` 并使用新的空 `results/` 和 `filters/`，不要覆盖随附证据；重新生成过滤器前安装上述依赖。CPU 生产程序要求编译目标支持 AVX-512，GPU 默认架构为 `native`，其他架构应重新做数值和性能验证。
