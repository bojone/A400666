# a(14)：用指数周期把方程降为一次同余

**中文 | [English](README.en.md)**

## 结论与证据

$$\boxed{a(14)=675924569493048966}$$

完整复合模数验证为：

$$c(675924569493048966)\bmod 1234567891011121314=0.$$

搜索覆盖 $`14 < k < 10^{18}`$：17 位及以下没有解，18 位区间只得到这个解。其轨道参数为

$$x=1484703107343807,\qquad t=177,$$

并且 $`x+Qt=675924569493048966`$、$`k\bmod6=0`$。

主要证据：

- [完整分片审计](results/d18_x0.candidates)：18 位唯一候选的主机复核记录。
- [原始管理日志](manager.log)：8 张 GPU 的任务队列和结束状态。
- [分片状态与日志](results/)：36 个分片的配置、断点和 `DONE` 记录。
- [前 13 项复核](oeis_results/verification.txt)：整除性及每个公布值之前的穷举结果。

## 1. 模数分解与初筛

$$c(14)=1234567891011121314=2\cdot3\cdot p,$$

$$p=205761315168520219.$$

这里 $`p`$ 是素数。$`c(k)`$ 与 $`k`$ 的末位奇偶性相同；模 3 用数字和可得

$$c(k)\equiv\sum_{i=1}^{k}i=\frac{k(k+1)}2\pmod3.$$

因此只需保留 $`k\bmod6\in\\{0,2\\}`$，再要求 $`c(k)\equiv0\pmod p`$。所有最终候选仍用完整的 $`c(14)`$ 验证，避免把素因子条件误当作充分条件。

## 2. 固定位数区间中的闭式

令 $`r_k=c(k)\bmod p`$。若 $`k`$ 的十进制位数固定为 $`d`$，写 $`q=10^d\bmod p`$，则

$$r_k=qr_{k-1}+k\pmod p.$$

定义

$$A=\frac1{1-q}\pmod p,\qquad B=-\frac q{(1-q)^2}\pmod p.$$

这些定义要求 $`q\ne1\pmod p`$。所有生产区间都满足该条件，下文需要求逆的系数也都非零，因此这些公式是良定义的。

于是

$$r_k=Uq^k+Ak+B\pmod p,$$

其中 $`U`$ 由区间起点 $`s`$ 决定：

$$U=\left(r_{s-1}-A(s-1)-B\right)q^{-(s-1)}\pmod p.$$

这样无需从 $`1`$ 开始逐项拼接。不过，若直接枚举 18 位整数，仍有约 $`9\times10^{17}`$ 个候选，下一步的周期降维才是关键。

## 3. 18 位区间

分解

$$p-1=54Q,\qquad Q=3810394725342967,$$

其中 $`Q`$ 也是素数，并且

$$\mathrm{ord}_p(10^{18})=Q.$$

把 $`k`$ 唯一写成 $`k=x+Qt`$，其中 $`0\le x < Q`$。由于 $`q^{x+Qt}=q^x`$，零剩余方程变成

$$Uq^x+Ax+B+AQt\equiv0\pmod p.$$

对固定 $`x`$，$`t`$ 只出现在一次项中：

$$t\equiv-\left(Uq^x+Ax+B\right)(AQ)^{-1}\pmod p.$$

18 位区间内只需检查 $`0\le t\le236`$ 以及真实区间端点。因此工作量从约 $`9\times10^{17}`$ 个整数降为 $`Q`$ 个轨道点，约降低 236 倍。

将上式写为

$$t(x)=\alpha q^x+\beta x+\gamma\pmod p,$$

$$\alpha=-U(AQ)^{-1},\qquad \beta=-Q^{-1},\qquad \gamma=-B(AQ)^{-1}\pmod p.$$

维护 $`z_x=\alpha q^x`$ 和 $`w_x=\beta x+\gamma`$，就有

$$z_{x+1}=qz_x,\qquad w_{x+1}=w_x+\beta\pmod p.$$

每个轨道点只需一次定模乘和少量模加。

## 4. 17 位及更低位区间

17 位区间按初筛结果写成

$$k=a+6j,\qquad a\in\\{0,2\\}.$$

此时 $`g=10^{17\cdot6}\bmod p`$ 的阶仍为 $`Q`$。再写 $`j=x+Qt`$，对固定 $`x`$ 又可解关于 $`t`$ 的一次同余：

$$t\equiv-\left(Uq^a g^x+Aa+B+Ahx\right)(AhQ)^{-1}\pmod p,\qquad h=6.$$

两个剩余类各扫描 $`Q`$ 个点，共 $`2Q`$ 个点，覆盖约 $`9\times10^{16}`$ 个 17 位整数。

不超过 16 位时，直接按步长 6 扫描更划算：用 $`r_k-Ak-B=Uq^k`$ 齐次化，指数部分每步一次模乘，线性部分用加法更新。所有阶段合计

$$14,764,517,509,362,229$$

个轨道点。精确的任务边界由 [src/run_all.py](src/run_all.py) 的 `make_tasks()` 生成，而不是在文档中另行估计。

## 5. GPU 实现与分片

使用 8 张 NVIDIA GPU：

- GPU 0–1：完整 18 位区间，各 $`Q/2`$ 个点。
- GPU 2–5：17 位区间的两个模 6 剩余类，每类再分两片。
- GPU 6–7：16 位及以下区间，共 30 个任务。
- 总计 36 个独立分片。

每个线程从任意轨道位置用快速幂初始化，然后连续处理 65,536 个点。单卡实测约每秒 $`3.9\times10^{11}`$ 到 $`4.4\times10^{11}`$ 个轨道点，全量约 80 分钟。

对于使用周期降维的路径，核心循环为：

```text
z = alpha * g^x mod p
w = beta * x + gamma mod p

repeat:
    t = (z + w) mod p
    if t is in the permitted small range:
        reconstruct k
        check interval boundaries and k mod 6
        independently verify every reported hit

    z = Montgomery_multiply(z, gR)
    w = (w + beta) mod p
    x = x + 1
```

核心为 64 位 Montgomery 模乘，$`R=2^{64}`$。让轨道值保持普通表示，固定乘数保存为 $`gR\bmod p`$，则

$$\mathrm{Mont}(z,gR)=zg\pmod p.$$

输出仍是普通表示，可直接进入下一轮，省去逐点表示转换。

每个 CUDA kernel 完成后，主机将配置、`next_x`、命中数等原子写入 `.state`。在当前配置下，一次 kernel 约运行一秒，因此中断后最多重算最近一个 kernel。命中先写入 `.candidates`，再用独立公式复核。状态中的配置必须匹配当前任务，不能把不同区间的断点混用。由于每个线程都能从任意 $`x`$ 用快速幂独立初始化，任务可以按任意区间拆分、恢复和迁移，而不必从区间起点顺序计算。

## 6. 独立余数验证

[src/verify.py](src/verify.py) 的块和法直接适用于完整复合模数，不使用搜索阶段的模逆元或周期性质。

对固定 $`d`$ 位整数组成的块，设首项为 $`s`$、项数为 $`n`$、$`q=10^d`$，定义

$$S_0(n)=\sum_{i=0}^{n-1}q^i,\qquad S_1(n)=\sum_{i=1}^{n}iq^{n-i}.$$

整块递推为

$$r_{\mathrm{end}}=r_{\mathrm{start}}q^n+(s-1)S_0(n)+S_1(n)\pmod{c(14)}.$$

相邻长度 $`a,b`$ 的块可以倍增合并：

$$S_0(a+b)=q^bS_0(a)+S_0(b),$$

$$S_1(a+b)=q^bS_1(a)+aS_0(b)+S_1(b).$$

这使验证只需加法和乘法，即使模数不是素数也成立。$`a(15)`$ 复用了同一个通用函数；该文件里的 `M14` 自检常量并不表示通用 `concat_mod()` 只能验证 $`a(14)`$。

本实现通过的检查包括：

- 截至 1000 的逐项直接拼接，以及 110 个大 $`k`$ 对照，均与独立快速公式一致。
- 100,000 组随机 GPU Montgomery 模乘与宿主端 128 位计算一致。
- 候选 `675924569493048966` 在完整复合模数下余数为 0；全部 36 个分片的配置、终点和完成日志通过审计。
- OEIS 前 13 个公布值的整除性和最小性复核，详见下一节。

## 8. 审计、构建与重跑

从本项目根目录执行：

```bash
# 不需要 GPU：复核块和法、自检、36 个分片及所有保存候选
make -C a14 audit

# 不需要 GPU：读取前 13 项的完整覆盖证据
make -C a14 verify-first13

# 编译；可覆盖 NVCC 或 GPU_ARCH
make -C a14 NVCC=/usr/local/cuda-12.9/bin/nvcc GPU_ARCH=native

# 小规模 CUDA 数值自检，不重扫整个区间
make -C a14 selftest GPU_ID=0
```

完整重跑入口为 `cd a14/src && python3 run_all.py`，然后 `python3 audit_results.py`。它使用 8 张 GPU，当前目录已有断点时会续跑。要真正从零复核，请复制源码并在新的工作目录建立空的 `results/`；不要把不完整的新结果混入本项目的完成证据。

前 13 项的 GPU 重扫入口为 `cd a14/src && python3 verify_first13.py`；`--audit` 只读取已有结果。`verify_oeis selftest 0` 则仅运行数值自检。
