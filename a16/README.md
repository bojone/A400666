## 1. 分解与搜索空间

$$c(16)=12345678910111213141516=4p_1p_2,$$

其中

$$p_1=1231026625769,\qquad p_2=2507191691.$$

它们的前驱分解为

$$p_1-1=2^3\cdot29\cdot113\cdot1993\cdot23561,$$

$$p_2-1=2\cdot5\cdot1381\cdot181549.$$

对于相关的 $`k`$，必须有 $`4\mid c(k)`$，因此写 $`k=4j`$。这里不再面对 a14、a15 那样的巨大素因子：两个素数模数都可用廉价的 64 位运算处理，而且 $`p_1`$ 的模幂周期特别有利。

本构建实际使用的所有数位区间 $`2\le d\le28`$ 都满足

$$L=\mathrm{ord}_{p_1}(10^{4d})=153878328221.$$

29 位的阶不同，因此管理程序和 CUDA 初始化都会明确拒绝它。答案已经在 23 位区间找到并完成审计，所以不需要处理 29 位。

## 2. 主扫描：每个轨道点解一次线性同余

在固定位数 $`d`$ 的区间内，令 $`q=10^d\bmod p_1`$，使用闭式

$$c(k)\equiv Uq^k+Ak+B\pmod{p_1},$$

$$A=(1-q)^{-1}\pmod{p_1},\qquad B=-q(1-q)^{-2}\pmod{p_1}.$$

其中 $`U`$ 由区间起点的余数确定。令

$$g=q^4,\qquad D=4AL,\qquad j=x+Lt,\qquad 0\le x < L.$$

此时 $`g^x`$ 以 $`L`$ 为周期，零剩余条件可以化为对 $`t`$ 的一次同余：

$$t_*=\alpha g^x+\beta x+\gamma\pmod{p_1},$$

$$\alpha=-UD^{-1},\qquad \beta=-L^{-1},\qquad \gamma=-BD^{-1}\pmod{p_1}.$$

所有真实解都满足 $`t=t_*+mp_1`$，其中 $`m\ge0`$ 为整数。CUDA 循环会检查所有使 $`j`$ 落在实际区间内的 $`t`$，而不是只检查 $`t_*`$ 本身。$`j`$ 和 $`k`$ 使用两个 64 位字表示，因此超过 $`2^{64}`$ 的候选也不会溢出。

kernel 维护

$$z_x=\alpha g^x,\qquad w_x=\beta x+\gamma\pmod{p_1},$$

每点进行一次 Montgomery 模乘和少量加法。固定乘数保存为 Montgomery 缩放形式，轨道值保持普通表示，因此不需要逐点转换表示。

每个区间分给 8 张 NVIDIA GPU。每个线程最多处理 65,536 个连续轨道点，每个 CUDA block 含 256 个线程，每次启动 512 个 block。每次启动结束后，程序以原子替换方式写入 `.state`，保存精确配置、`next_x`、主素因子命中数和完整命中数。已经完整完成的分片在重启时直接跳过。

## 3. 用四张窗口表复核第二个素数

主素因子命中只证明 $`p_1`$ 整除。第二个条件在同一个 kernel 内独立复核。

对相同数位区间，令 $`q_2=10^d\bmod p_2`$、$`g_2=q_2^4`$、$`h=g_2^L\bmod p_2`$。使用对应的 $`U_2,A_2,B_2`$，第二个余数为

$$r_2=U_2g_2^x h^t+4A_2x+B_2+(4A_2L)t\pmod{p_2}.$$

与 $`x`$ 有关的项逐步更新。可能很大的 $`h^t`$ 用四张表计算：

$$T_s[i]=h^{2^{16s}i}\bmod p_2,\qquad s\in\\{0,1,2,3\\},\qquad 0\le i < 65536.$$

任意 64 位 $`t`$ 都可写成四个 $`2^{16}`$ 进制数位，因此查表求幂只需四次查表和至多三次模乘。每张 GPU 的表占 1 MiB，并在每个数位区间重新生成，避免对每个主素因子命中都执行完整快速幂。

只有两个素数模数同时为零且 $`4\mid k`$，才证明完整的 $`c(16)`$ 整除。宿主端 C++ 会再次检查保存候选的两个素数余数，随后 Python 在完整复合模数下独立复核。

## 4. 覆盖与最小性

对数位 $`d`$，搜索边界为

$$j_{\min}=\left\lceil\frac{\max(17,10^{d-1})}{4}\right\rceil,\qquad j_{\max}=\left\lfloor\frac{10^d-1}{4}\right\rfloor.$$

每个 $`x\in[0,L)`$ 恰好分配给 8 个分片之一，并检查所有允许的 $`t`$。若 $`j_{\max}+1 < L`$，分片终点直接截断到 $`j_{\max}+1`$，避免扫描无关轨道。只有前一个数位的所有分片都到达精确终点并通过审计，才开始下一个数位。

生产搜索的部分计数为：

| 数位区间 | 主素因子命中 | 完整解 |
|---|---:|---:|
| 22 | `1827789172` | 0 |
| 23 | `18277398093` | 10 |

主流程用时 **277.448 秒**，包含编译自检、设备初始化、断点续跑和最终审计。它复用了已经完成的 2–6 位试跑断点；最初的端到端试跑另耗时 69.346 秒。设备为 8 张 NVIDIA GPU，CUDA 版本为 12.9。这些是实测记录，不代表其他硬件或空目录从零重跑时的性能。

## 5. 数值与独立验证

CUDA 自检包括：

- 10 万组 Montgomery 模乘与宿主端 128 位计算对照。
- 10 万组查表求幂与普通模幂计算对照。
- 截至 1000 的拼接和 100 个较大输入的两种宿主公式对照。

另一次正向对照覆盖 20 位区间前 100 万个轨道点：GPU 和 Python 都得到 **114 个主素因子命中**，完整候选集合完全一致，见 [formula20_test.audit.txt](results/formula20_test.audit.txt)。

[src/verify16.py](src/verify16.py) 使用独立的二进制块和法。对于首项为 $`s`$、项数为 $`n`$、位数为 $`d`$ 的块，令 $`q=10^d`$，计算

$$r_{\mathrm{end}}=r_{\mathrm{start}}q^n+(s-1)S_0(n)+S_1(n),$$

其中

$$S_0(n)=\sum_{i=0}^{n-1}q^i,\qquad S_1(n)=\sum_{i=1}^{n}iq^{n-i}.$$

该方法只需要加法和乘法，可直接在完整复合模数 $`c(16)`$ 下工作，不使用主搜索的周期降维公式。最小候选还使用 [a15/src/verify15_matrix.py](../a15/src/verify15_matrix.py) 的矩阵快速幂验证，余数同样为 0。

最终审计检查每个分片的配置、终点、完成日志、候选位数、$`k\bmod4`$、两个素数余数和完整模数余数，并确认更低位区间没有保存的解。与其他项目相同，读取审计不等于从零重新穷举：最小性同时依赖完整覆盖证据和独立候选检查。


```bash
cd a16/src
python3 run16.py --through 28
```

它使用 8 张 GPU，并从有效断点继续。若要从零独立重跑，请将源码复制到新的工作目录并使用空的 `results/`，不要把不完整的新结果混入完成证据。支持范围明确限定为 2–28 位；29 位需要不同的周期，而本答案并不需要进入该区间。
